# gh skill writes namespaced lock keys for flat installations, breaking skills update

## Body

### Describe the bug

For a namespaced skill, `gh skill` installs a flat directory but records the namespaced name in the shared `~/.agents/.skill-lock.json`. The Vercel `skills` CLI then treats that lock entry as missing and fails to update it.

### Affected versions

- GitHub CLI `2.105.0`
- `skills` CLI `1.9.0`

### Steps to reproduce

1. Install a GitHub-hosted namespaced skill with `gh skill install`, using user scope.
2. Compare its flat installed directory name with its namespaced entry in `~/.agents/.skill-lock.json`.
3. Run `skills update --global`.

### Expected vs actual behavior

The shared lock entry should be compatible with the installed directory and the `skills` updater. Instead, the updater reports the namespaced entry as missing and fails with `No matching skills found`.

### Investigation

The installer [records `skill.InstallName()`](https://github.com/cli/cli/blob/v2.105.0/internal/skills/installer/installer.go#L79), which includes the namespace, but [installs using the flat `skill.Name`](https://github.com/cli/cli/blob/v2.105.0/internal/skills/installer/installer.go#L250-L254). The lock file is intended for [Vercel CLI interoperability](https://github.com/cli/cli/blob/v2.105.0/internal/skills/lockfile/lockfile.go#L17).

Removing the duplicate namespaced lock entries while retaining the unprefixed entries and installed files restored `skills update --global`. Future `gh skill` installs or updates may recreate them.

### @wellparth - 2026-11-25T06:49:08Z

Hi maintainers 👋

I've diagnosed the root cause and submitted PR #15158 with the fix and regression test coverage:
1. Records `skill.Name` instead of `skill.InstallName()` in `.skill-lock.json` so lockfile keys match the flat directory layout on disk, unblocking Vercel `skills update`.
2. Resolves the directory name with `filepath.Base` in `printFileTree`, resolving the `(could not read directory)` error noted in the triage reproduction above.
3. Adds regression tests for single and batch installs, and tree rendering (incorporating Copilot code review recommendations).
